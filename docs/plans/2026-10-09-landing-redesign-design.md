# 랜딩 리디자인: "와인 라벨" 방향 (2026-10-09)

## 문제
기존 사이트는 LLM 랜딩 기본값(검정 배경 + 보라 블러, 그라데이션 텍스트, 글래스 카드, 알약 배지, Tailwind 무지개, SVG 와이어프레임 일러스트, 범용 카피)이 그대로 들어가 있어 생성물로 읽혔다.

## 결정
- **종이 위 잉크, 보라는 두 곳.** 바탕 `#F6F2EA`, 글 `#1B1A17`, 보라 `#7E13B1`은 App Store 버튼과 헤더 워드마크에만.
- **서체는 Pretendard 하나.** 제목은 700, 자간 -0.03em. 세리프는 "DRINKI G" 워드마크 이미지에만 남긴다. (Noto Serif KR을 시도했다가 촌스럽다는 피드백으로 되돌림.)
- **실제 화면이 주인공.** 앱스토어 스크린샷 4장(라벨 스캔, 페어링, 테이스팅 노트, 셀러)을 흰 배경 제거(누끼) 후 사용. 이미지 아래 캡션은 두지 않는다(alt에만).
- **카드 대신 헤어라인.** 섹션과 기능 행은 `border-paper-line` 한 줄로만 나눈다. 블러, 그라데이션, 글로우 없음.
- **카피는 앱스토어 문구를 재사용.** "메뉴만 고르세요, 와인은 맡기세요", "그 와인 뭐였지? 까먹지 말고 기록하세요" 등. "AI", "완벽하게", "모든 것", "여정" 금지.
- **모션은 히어로 진입 한 번.** 스크롤 fadeUp 전부 제거.
- **브랜드 자산:** Drinky 3D(하트) → "드링키지는" 섹션, 클레이 와인병 → 마지막 CTA(잉크 배경).

## 구조
Hero → 기능 4행(교차 배치) → 사용 방법 3단 → 드링키지는 → CTA(잉크 띠) → 푸터

## 남은 것
- 히어로 목업(`Mockup.webp`)은 680px 원본이라 레티나에서 약간 소프트하다. 고해상도 원본을 받으면 교체.
- OG 이미지는 아직 다크 버전.

## 2차 수정 (같은 날, 피드백 반영)
- 카피 전부 한 줄로. 본문 문단 금지. ("구구절절 줄글" 피드백)
- 바탕에 파스텔 워시(라일락·블러시·버터)와 브랜드 그라데이션 라인(보라→라일락→블러시→버터)을 히어로 바닥, CTA 띠 위, 내비 호버 밑줄에 넣음. Cabine의 탭 밑줄과 로딩 오버레이에서 가져온 것.
- 모션: 글은 12px 떠오름, 사진은 블러가 걷히며 나타남(resolve), 버튼은 호버 시 1px 뜨고 보라 그림자. 전부 한 번만, reduced-motion 존중.
- 이미지 캡션 제거.

## 3차 수정: 모션 보강 ("모션이 너무 없다" 피드백)
- 헤더: 스크롤 진행 바(브랜드 그라데이션, 스프링), 현재 섹션을 따라다니는 밑줄(IntersectionObserver + aria-current).
- 히어로: 제목 단어 단위 스태거, 목업은 블러 해제 후 7초 주기로 떠다님, 바닥 그라데이션 라인이 왼쪽에서 그어짐, 워시는 22초 주기로 천천히 흐름(CSS keyframes), 보조 버튼 화살표 호버 슬라이드.
- 기능 프레임(`components/PhoneFrame.tsx`): 스크롤 패럴랙스(폰 ±48px, 워시 반대 방향 ±6%), 마우스 따라 기우는 3D 틸트(스프링), 블러 해제 등장.
- 사용 방법: 각 단계 위 선이 왼쪽에서 그어지며 스태거.
- 드링키지는: 캐릭터 떠다님, 항목 스태거.
- CTA: 와인병 떠다님.
- 전부 MotionConfig reducedMotion="user"와 CSS prefers-reduced-motion을 따른다.
- 사용 방법은 로드맵: 선이 01 → 02 → 03으로 0.8초씩 그어지고, 선이 닿는 순간 숫자가 튀어나온 뒤 글이 뒤따른다. 노드는 동그라미 없이 숫자만(동그라미는 거절됨). 데스크톱 가로, 모바일은 단계 사이 세로 구간선.

## 매장 도입 문의 페이지 (2026-10-10)
- `/stores`, `/en/stores`. 메시지 순서: 모르는 손님은 두 번째로 싼 와인을 시킨다 → 안 맞으면 매장 탓이 된다 → QR 하나로 취향·예산에 맞는 병을 골라준다 → 지금은 무료.
- 구성: 히어로 → 손님의 사정 → 작동 방식(4단계 로드맵, `components/Roadmap.tsx` 공용) → 매장이 얻는 것 3줄 → 준비할 것 · 비용 → 문의 폼(잉크 띠).
- 폼은 서버 없이 mailto로 sean@gourmevel.com에 제목·본문을 채워 메일 앱을 연다. 주소는 화면에 노출하지 않는다.
- 홈에는 "드링키지는"과 CTA 사이 한 줄 띠, 헤더·푸터 링크만. 소비자 랜딩과 매장 피칭은 페이지를 분리한다.
- 아직 없는 제휴 매장 로고·후기·숫자는 넣지 않는다.
- 문의 폼은 mailto 대신 `api/inquiry.ts`(Vercel Node Function)로 POST → Gmail SMTP(nodemailer)로 메일. 환경변수 `GMAIL_USER`, `GMAIL_APP_PASSWORD` 필수, `INQUIRY_TO` 선택(기본은 보내는 계정 자신). 외부 서비스 가입·도메인 인증 불필요. (Slack은 사용자가 안 써서, Resend는 가입이 필요해서 뺌.) vercel.json의 SPA 리라이트는 `/api/`를 제외하도록 변경. 성공 시 "문의가 접수되었습니다 / 48시간 안에 연락" 팝업.

## 매장 QR 손님 웹앱 + 어드민 매장 관리 (2026-10-10)
설계 결정: 매장 와인은 와인 DB와 **이름 매칭을 하지 않는다**. 매장이 부르는 이름·가격·다섯 수치(당도·산도·타닌·바디·알코올 1~5)를 그대로 저장하고, 추천은 그 수치로만 계산한다(앱 추천과 같은 거리식, 100 − 차이합×4). 와인 DB 연결은 사진을 붙이기 위한 선택이며 어드민에서 검색해 ID로 붙인다.

- **서버(drinkig-server, 브랜치 `feat/store-qr`, 미커밋)**: `domain/store` — Store(slug=QR 코드), StoreWine, StoreEvent. 공개 `/store/**`(nearby, {slug}, {slug}/recommend, {slug}/event)는 SecurityConfig permitAll + JWTFilter 통과. 어드민 `/admin/store/**`(목록·등록·수정·상태, 와인 목록, CSV 업로드, 와인 수정/삭제, 통계). CSV는 한글·영문 헤더, "45,000원" 가격, UTF-8/MS949 모두 처리하며 오류가 하나라도 있으면 아무것도 반영하지 않는다(전부 아니면 전무). 단위 테스트 7개 통과.
- **어드민(Drinkig-Web)**: `/admin/stores` 목록+추가, `/admin/stores/:id` 상세(정보 수정, 노출 토글, CSV 업로드, 와인 리스트·사진 연결·숨김·삭제, QR PNG 1024px 다운로드, 최근 30일 통계).
- **손님 웹앱(Drinkig-Web)**: `/s` 근처 매장(위치 허용 시 3km→20km→전체), `/s/{slug}` intro → 질문 5개(일상 말, '잘 모르겠어요') → 예산 슬라이더+종류 → 결과(점수순, 예산 밖은 따로). 세션 id로 VISIT/TASTE_SUBMIT/RESULT_VIEW/WINE_CLICK 이벤트. 종이 톤, 모바일 전용, 클라이언트 전용 라우트(main.tsx가 프리렌더 안 된 경로는 hydrate 대신 새로 렌더).
- **배포 전 확인**: 서버 CORS 허용 목록(`app.cors.allowed-origins`, CD 시크릿 APPLICATION)에 `https://www.drinkig.com` 포함 여부. ddl-auto=update라 테이블은 자동 생성.
- **미구현(다음)**: 결과 화면의 카카오 로그인 → 취향 저장 → 앱 유도. 지금은 App Store 링크만.
